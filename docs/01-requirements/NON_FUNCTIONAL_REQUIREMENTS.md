# Non-Functional Requirements

> v0.3 adds the measurable target table (GAP-083). v0.2 declared targets to be hypotheses and gave
> none, while `OBSERVABILITY_AND_SLO.md` independently stated five with no cross-reference.
> **This document is now the single normative source for targets; the SLO document derives from it.**

## 1. Requirements

- **NFR-001 Reliability [P0]** AI unavailability shall not remove deterministic fallback control
  capability. **Extended in v0.3:** this holds for the failure of *any single* platform component,
  including the Safety Supervisor itself (ADR-0011), not only the inference service.
- **NFR-002 Traceability [P0]** A recommendation and resulting command shall be traceable from
  telemetry window → prediction → safety decision → command result using `correlationId` and
  `causationId`.
- **NFR-003 Observability [P0]** All application services shall emit structured logs, health
  metrics, and traces where cross-service latency matters.
- **NFR-004 Recoverability [P0]** Gateway and consumers shall recover from transient dependency
  failures without manual process restart in documented scenarios.
- **NFR-005 Reproducibility [P0]** Load and failure claims shall be generated by repository
  scripts/configuration with recorded environment metadata.
- **NFR-006 Security [P0]** Secrets shall not be committed; service authentication and
  least-privilege design shall be documented before cloud deployment. **Extended in v0.3:** command
  origin shall be authenticated, never self-asserted (ADR-0016).
- **NFR-007 Maintainability [P0]** Public contracts shall be independent from internal
  implementation types.
- **NFR-008 Compatibility [P0]** Contract-breaking changes require explicit schema versioning and
  migration notes.
- **NFR-009 Portability [P0]** Baseline must run locally with containerized dependencies;
  Kubernetes deployment is a separate deployment profile.
- **NFR-010 Testability [P0]** Fault injection shall be deterministic/configurable enough for
  automated integration tests.
- **NFR-011 Performance [P0]** All values in §2 are **TARGETS, not measured results.** No published
  figure may be presented as measured until produced by a repository load/failure script with
  recorded environment metadata.
- **NFR-012 Scope discipline [P0]** New infrastructure components require an ADR showing a
  requirement that cannot reasonably be met with existing components.
- **NFR-013 Determinism [P0] (new)** Feature aggregation shall be restart-invariant: the same
  telemetry range shall yield byte-identical features regardless of consumer restarts (ADR-0018).
- **NFR-014 Fail-closed [P0] (new)** Where a safety-relevant input cannot be validated — invalid
  configuration, unreadable control state, stale model authorization — the system shall fail closed
  to a more conservative state, never open to a permissive one.

## 2. Target table

> **Every value below is `TARGET (unmeasured)`.** Reports under `reports/` will carry measured
> values with environment metadata; until then no number here may be quoted as a result.

### 2.1 Throughput

| ID | Metric | Demo target | Load target |
|---|---|---|---|
| T-01 | Telemetry ingest | 200 ev/s (20 eq × 10 Hz) | 2 500 ev/s (250 eq × 10 Hz) |
| T-02 | Predictions | 4/s (20 eq ÷ 5 s) | 50/s |
| T-03 | Safety decisions | 4/s | 50/s |
| T-04 | Commands | ≤ 4/s | ≤ 50/s |
| T-05 | 1 s aggregate writes | 20 rows/s | 250 rows/s |

### 2.2 Latency

| ID | Metric | P95 | P99 |
|---|---|---|---|
| L-01 | Gateway normalise + publish | 20 ms | 50 ms |
| L-02 | Telemetry → feature window available | 200 ms | 500 ms |
| L-03 | Inference | 300 ms | 500 ms |
| L-04 | Safety decision (prediction receipt → decision published) | 250 ms | 500 ms |
| L-05 | Safety gate evaluation only | 50 ms | 100 ms |
| L-06 | Command apply (receipt → OT write ack) | 150 ms | 400 ms |
| L-07 | **End-to-end telemetry → applied command** | **1 200 ms** | 2 500 ms |
| L-08 | Operations API equipment summary | 100 ms | 300 ms |
| L-09 | Correlation trace query | 200 ms | 500 ms |
| L-10 | **Quarantine propagation (registry → Supervisor effective)** | **2 000 ms** | 5 000 ms |

L-07 is the number a reviewer will ask for. It is the sum of L-01, L-02, L-03, L-04, and L-06 plus
Kafka hops, and it must be **well inside** the 5 s inference cadence, or decisions would queue.

### 2.3 Recovery

| ID | Scenario | Target |
|---|---|---|
| R-01 | Gateway reconnect after protocol restore | ≤ 10 s, **no process restart** (FR-004) |
| R-02 | Kafka consumer resume after broker restart | ≤ 30 s |
| R-03 | **Supervisor silence → fallback applied** | **≤ 12 s** (watchdog, ADR-0011) |
| R-04 | **Equipment dead-man revert** | **≤ 30 s** after last setpoint refresh |
| R-05 | Supervisor restart → AI authority re-earned | ≤ 35 s (30 s hold + 1 cadence) |
| R-06 | Control Service restart → ready | ≤ 15 s |
| R-07 | **Publisher death → models unauthorized** | **≤ 90 s** (3 missed watermarks) |
| R-08 | Projection rebuild from Kafka (6 h telemetry) | ≤ 10 min |

### 2.4 Data integrity

| ID | Property | Target |
|---|---|---|
| D-01 | Duplicate command effect | **zero**, for identical idempotency key |
| D-02 | Telemetry loss during Kafka outage | bounded by the 6 000-event buffer, **counted and flagged**, never silent |
| D-03 | Undetected telemetry loss | **zero** — every gap raises `SEQUENCE_GAP` |
| D-04 | Decisions missing a correlation ID or reason code | **zero** |
| D-05 | Fabricated sensor values | **zero** — a bad reading is `null`, never substituted |
| D-06 | Clock skew between platform hosts | ≤ 250 ms |
| D-07 | Feature aggregation determinism | byte-identical across restart (NFR-013) |

D-02 and D-03 are deliberately different: bounded loss is acceptable, **undetected** loss is not.

### 2.5 Availability

| ID | Metric | Target |
|---|---|---|
| A-01 | Control Service availability during AI outage | 99.9 % of the test window |
| A-02 | Deterministic control availability during **Supervisor** outage | **100 %** — fallback is applied within 12 s (ADR-0011) |
| A-03 | Deterministic control availability during Kafka outage | 100 % — command path is gRPC (ADR-0009) |
| A-04 | Dashboard availability | not control-relevant; best effort |

A-02 is the target that did not exist in v0.2 and is the one the architecture was changed to make
achievable.

## 3. How these become measured

Each target maps to a script under `tests/load/` or `tests/failure/`, which writes a report to
`reports/` carrying git commit, deployment profile, machine specification, duration, configuration,
observed metrics, and pass/fail against the AC ID (`RUNBOOK_AND_FAILURE_TESTS.md`). A target with no
report remains explicitly unmeasured, and is labelled as such wherever it is displayed.
