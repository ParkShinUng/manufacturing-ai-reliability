# v0.3 Approval Checklist

Work through this, then record the outcome in `HUMAN_APPROVAL.md`.

## Product direction
- [ ] The product is a **Manufacturing AI Reliability Platform**, not an ML demo, and the docs reflect that
- [ ] The portfolio thesis — *AI must never become a new single point of failure* — is clear and defensible
- [ ] Scope exclusions are acceptable (no 3D twin, no Lakehouse, no LLM copilot, no manual control)

## Architecture
- [ ] The three-layer authority model (L1 advisory / L2 application control / L3 equipment self-protection) is understandable
- [ ] The command path is independent of Kafka, MLflow, PostgreSQL, and the dashboard
- [ ] Service boundaries are explicit and each service has a design document
- [ ] Every major technology has a documented requirement justifying it

## Control and safety
- [ ] **HD-003**: Control Service writing autonomously on watchdog is acceptable
- [ ] The equipment dead-man revert is acceptable
- [ ] 13 safety gates, all-must-pass, no partial-trust path, is acceptable
- [ ] OOD as a hard reject is acceptable
- [ ] `STOP_REQUIRED` exiting only by operator acknowledgement is acceptable
- [ ] Removing the manual command origin (**HD-002**) is acceptable

## Risk
- [ ] **HD-001**: 60 s maximum authorization staleness is acceptable
- [ ] The six open risks in `OPEN_RISKS.md` are acceptable
- [ ] **R-01 understood**: every performance figure is an unmeasured target
- [ ] **R-03 understood**: this demonstrates recovery, not high availability
