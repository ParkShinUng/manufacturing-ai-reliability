# Codex challenge - ADR-0021 (Kafka client and broker runtime)

> Raw output, transcribed verbatim from the `codex exec` run of 2026-09-28. Read-only, with fact
> checking against nuget.org, Docker Hub and the Apache and Confluent documentation.
> Verdict: ACCEPT_WITH_CONDITIONS.

F-001 - P1 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:71,78,145` - The ADR claims tests and local runtime use the same image tag, but the decision only pins `Testcontainers.Kafka` as a package, not the broker image passed to it. Testcontainers’ .NET module docs show module defaults/examples around `confluentinc/cp-kafka`, while `apache/kafka:4.3.1` must be explicitly supplied. - This can silently make integration tests run Confluent Kafka while compose runs Apache Kafka, defeating driver 4. - Fix: require the Testcontainers builder to use `apache/kafka:4.3.1@sha256:...`, and add that exact image assertion to acceptance conditions. Sources: NuGet Testcontainers.Kafka 4.15.0, Testcontainers modules docs, Apache Kafka Docker docs.

F-002 - P1 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:147` - “Admin API confirmed to support ... fail rather than mutate when a partition count differs” is misframed. Confluent’s AdminClient supports `CreatePartitionsAsync`, i.e. increasing partitions; refusing a partition-count change is repository bootstrap policy, not a Kafka/AdminClient guarantee. - A later implementation could accidentally call the mutation API and still say the client supports admin operations. - Fix: state that bootstrap must read topic descriptions/configs first and fail before calling `CreatePartitionsAsync`; test the negative case from `KAFKA-001`. Source: Confluent `IAdminClient` docs.

F-003 - P1 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:119-122`; `docs/03-contracts/KAFKA_TOPOLOGY_AND_SEMANTICS.md:235` - The ADR says section 11’s retry profile will be explicit, but `enable.idempotence=true` in Confluent/librdkafka automatically sets effectively unbounded producer retries unless overridden, while the topology says Kafka producer max attempts = 5. - This is a real semantic conflict: idempotent delivery, `message.timeout.ms=30000`, and “5 attempts with exponential backoff” are not the same failure model. - Fix: reconcile §11 before acceptance: either replace “max attempts 5” with bounded delivery timeout for Kafka producers, or document the exact Confluent settings and prove they preserve idempotent ordering. Source: Confluent `ProducerConfig.EnableIdempotence` docs.

F-004 - P1 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:137-148` - Acceptance conditions omit most context-table semantics: idempotent producer, `acks=all`, manual commit, seek/rewind, Supervisor `seekToEnd`, tombstones, and headers. - The challenge can confirm Confluent.Kafka can express them, but acceptance does not require proving the repo actually configured them. - Fix: add acceptance conditions or `KAFKA-*` smoke tests covering each selected-client semantic, especially Supervisor `seekToEnd` after assignment and null-valued tombstone production.

F-005 - P1 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:101-105,141-143` - The ADR correctly flags `librdkafka.redist` packaged license verification, but acceptance only audits that transitive native package. It does not require a full added graph scan for `Confluent.Kafka`, `Testcontainers.Kafka`, `Testcontainers`, Docker.DotNet, and any new transitive packages. - The repo’s current license claim is “29 packages, all permissive”; adding these dependencies changes that graph. - Fix: acceptance should require `scripts/license-scan.mjs` over the full restored graph after the packages are added, with package-file evidence for any `licenseUrl`/unidentified entries. Sources: NuGet Confluent.Kafka and librdkafka.redist package pages.

F-006 - P2 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:58,114,156` - Factual nuance: `apache/kafka:4.3.1` exists and Kafka 4.x is KRaft-only, but the ADR source says Docker tag updated `2026-06-23`; Apache’s official downloads page says 4.3.1 was released `2026-06-25`, while artifacts/images appear around June 23. - Not blocking, but the ADR should avoid mixing artifact timestamp and release date. - Fix: cite Apache downloads/release date separately from Docker tag/digest timestamp. Sources: Apache downloads, Apache upgrade docs.

F-007 - P2 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:14-26,137-148`; `docs/06-development/TEST_SPECIFICATIONS.md:283-293` - Serialization/schema validation is not decided. Phase 3’s shared consume-validate-DLQ component must preserve original payloads, validate JSON Schema, handle tombstones, and set headers, but ADR-0021 selects only the Kafka client and does not state whether messages are raw UTF-8 JSON bytes, strings, or Confluent serializers. - This will surface immediately in `KAFKA-002`. - Fix: record “raw JSON payload, repo JSON Schemas, no schema registry/serdes package” or create a separate ADR if adding a serializer/schema dependency.

F-008 - P2 - `docs/03-contracts/KAFKA_TOPOLOGY_AND_SEMANTICS.md:53-64,102-114`; `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:117-122` - Consumer group operational defaults are under-specified: group IDs are documented, but partition assignment strategy, static membership/client IDs, and Kafka 4.x group protocol behavior are not. - Kafka 4.0 introduced the new group coordinator / consumer rebalance protocol; leaving defaults implicit can change replay and rebalance behavior across client/broker upgrades. - Fix: either pin consumer assignment/protocol-relevant settings or explicitly defer them with an acceptance condition before Phase 3 consumers are built. Source: Apache Kafka 4.0 upgrade notes.

F-009 - P2 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:67-69,112-113` - Testcontainers as default is justified for isolation, but the ADR does not state when tests may be skipped or how CI without Docker is handled. - A Docker-required test suite can become flaky or silently excluded, undermining AC evidence. - Fix: add an operational condition: Docker-required integration tests must be marked, run in CI with Docker, and fail loudly or be explicitly excluded only in non-integration profiles. Source: Testcontainers .NET config docs.

F-010 - P3 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:46,58-59,67,152-157` - Checked factual claims mostly hold: `Confluent.Kafka 2.15.1` exists, is Apache-2.0 in NuGet metadata, was last updated 2026-09-10, and is net10.0-compatible; `Testcontainers.Kafka 4.15.0` exists, MIT, last updated 2026-09-06; `KafkaFlow 4.2.0` is MIT and depends on Confluent.Kafka; Redpanda Community is BSL/source-available; Kafka 4.x is KRaft-only. - This supports the direction, with the caveat that `librdkafka.redist` packaged `LICENSES.txt` still must be read as the ADR already says. - Fix: keep these sources, but distinguish package metadata from packaged license-file verification.

F-011 - P3 - `docs/07-adr/ADR-0021-kafka-client-and-broker-runtime.md:47,90-94`; `docs/08-roadmap/OPEN_DECISIONS.md:571-587` - Rejecting KafkaFlow on OD-009 grounds is sound, not self-serving. OD-009 deliberately bounded the shared component to validation, first-attempt DLQ, headers, post-DLQ commit, and no redrive; KafkaFlow is a framework layer over Confluent.Kafka with abstractions plus optional hosting/retry/schema/admin ecosystem packages. - The ADR’s rationale is aligned with the repo’s anti-framework boundary. - Fix: no blocker; maybe cite KafkaFlow’s NuGet dependency list to make the rejection evidence-based.

VERDICT: ACCEPT_WITH_CONDITIONS.
